01 URL base (producción)

Use preferentemente el proxy HTTPS del Frontend:

https://172.16.3.21/api

Acceso directo al Backend (red interna):

http://172.16.3.22:4000/api

Verificación pública (sin login):

https://172.16.3.21/api/verificar/solicitud/{id}

Portal ciudadano: https://172.16.3.21/verificar · ejemplo /verificar/000001.

02 Autenticación (JWT / cookies)

La app web usa cookies httpOnly (auth_token, refresh_token). Para integraciones: login → cookie de sesión o Authorization: Bearer <access_token> → refresh si expira.

Login

POST /auth/login

{
  "username": "aespinoza",
  "password": "123456"
}
Admin inicial de producción: aespinoza / 123456 (debe cambiarse). Para integraciones cree un usuario de servicio con permisos mínimos.

03 Endpoints principales

Todas las rutas se anteponen a la URL base (.../api).

Actas

  • GET /actas — params: page, limit, q, tipo, anio, numero (código completo = exacto; solo dígitos = folio), libro (2 o L2), fechas, dni
  • GET /actas/:id
  • POST /actas — requiere auth; cuerpo típico: persona_principal_id, tipo_acta, numero_acta, anio, fecha_acta

Personas / Solicitudes

  • GET /personas?q=... · POST /personas
  • GET /solicitudes · POST /solicitudes · PATCH /solicitudes/:id/atender

Verificación pública (sin auth)

curl -sk "https://172.16.3.21/api/verificar/solicitud/1"
{
  "valido": true,
  "constancia": {
    "numero": "000001",
    "tipo_solicitud": "COPIA_CERTIFICADA",
    "estado": "ATENDIDO"
  }
}

Importación, configuración, backup, salud

  • POST /importacion — multipart Excel + ZIP opcional; hasta 500 MB; esperas largas en Nginx
  • GET /configuracion · PUT /configuracion/url-verificacion (admin) → por defecto https://172.16.3.21
  • GET /backup/info · GET /backup/download (admin)
  • GET /health — esperado "status":"ok" y "services":{"db":"ok"}

05 Seguridad para integradores

  • CORS: origen permitido = FRONTEND_URL del Backend (https://172.16.3.21). Llamadas servidor-a-servidor no sufren CORS.
  • La API usa DB_SSL=true hacia 172.16.3.23 (interno).
  • No exponga usuario/contraseña de BD ni JWT en clientes públicos.
  • Preferir usuario de integración con permisos mínimos, no el admin aespinoza.
  • Verificación pública con rate limit.

06 Ejemplo rápido con curl

# Salud
curl -skf https://172.16.3.21/api/health

# Login (guarda cookies)
curl -sk -c /tmp/muni.jar -X POST https://172.16.3.21/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"aespinoza","password":"123456"}'

# Listar actas del libro 2, año 1940
curl -sk -b /tmp/muni.jar \
  "https://172.16.3.21/api/actas?libro=2&anio=1940&limit=20"

# Verificar constancia pública
curl -sk "https://172.16.3.21/api/verificar/solicitud/1"
