01 Para quién es y qué es el sistema

Manual para técnicos de sistemas o personal que administra la infraestructura en producción. Los manuales de instalación desde cero e integración API se documentan aparte.

Frontend = pantallas. Backend/API = lógica. PostgreSQL = base de datos. NFS = disco compartido. Nginx = recibe HTTPS y reparte el tráfico.

04 Nginx, puertos, SSL y carga masiva

Nginx corre en el host de 172.16.3.21 (no en Docker).

PuertoUso
80HTTP → redirige a HTTPS
443HTTPS de usuarios
3000Solo localhost (Next.js)
4000Backend en .22

Archivos: /etc/nginx/conf.d/muni-union-upstreams.conf, /etc/nginx/sites-available/muni-union, certificados en /etc/nginx/ssl/internal/ y /public/.

Carga masiva (producción)

client_max_body_size 500M;
client_body_timeout 300s;
proxy_send_timeout 360s;
proxy_read_timeout 360s;
send_timeout 360s;
location /api/     { proxy_pass http://backend; }
location /uploads/ { proxy_pass http://backend; }

Sin /uploads/ no se ven los documentos digitalizados. Tras editar: sudo nginx -t && sudo systemctl reload nginx.

URL de verificación (por defecto = IP)

Menú Configuración → valor por defecto https://172.16.3.21. Migración 006_configuracion_sistema.sql. Cambiar la URL en la app no configura sola Nginx/DNS.

05 Actualización y salud

# Backend (.22)
cd /opt/muni_union && git pull && bash deploy/deploy.sh backend

# Frontend (.21)
cd /opt/muni_union && git pull && bash deploy/deploy.sh frontend

curl -f http://172.16.3.22:4000/api/health
curl -skf https://172.16.3.21/api/health

Respuesta esperada: "status":"ok" y "services":{"db":"ok"}. No use deploy.sh all en una sola VM.

06 Backups

A) Desde la aplicación

Admin → Backup BD → descargar .sql. Usa la conexión a 172.16.3.23.

B) Desde la VM de base de datos

ssh deploy@172.16.3.23
sudo -u postgres pg_dump -Fc registro_muni_union \
  > /mnt/backups/manual_$(date +%F_%H%M).dump
ls -lh /mnt/backups/

Siempre haga backup antes de restaurar o migrar.

07 Migraciones, NFS y checklist

psql -h 172.16.3.23 -p 5432 -U app_user -d registro_muni_union \
  -f /opt/muni_union/back/src/migrations/006_configuracion_sistema.sql

NFS: uploads/logs en Backend; backups en PostgreSQL hacia .24.

  1. Cuatro VMs encendidas en orden.
  2. Health Backend y Frontend OK.
  3. Login admin y migración 006 si falta.
  4. Configuración URL = https://172.16.3.21.
  5. Probar verificación y backup.
  6. Nginx: 500M, /api/ y /uploads/.
