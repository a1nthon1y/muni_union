01 Descripción General

🏛️
Sistema de Registro Civil — STDU v2.0

Plataforma web para la gestión digital de registros civiles, solicitudes de copias certificadas, digitalización documental y auditoría de operaciones de la Municipalidad Distrital de La Unión.

El sistema permite registrar, editar, buscar y emitir documentos relacionados con los tres tipos de actas civiles: nacimiento, matrimonio y defunción. Adicionalmente gestiona las solicitudes de los ciudadanos que requieren copias certificadas, con control de estados, cobros y emisión de constancias verificables.

ℹ️
El sistema opera en dos modalidades de red: acceso interno (trabajadores de la municipalidad, LAN) y portal público de verificación de constancias (cualquier red, sin login).

02 Arquitectura del Sistema

El sistema implementa una arquitectura de tres capas separadas en contenedores Docker, con Nginx como único punto de entrada a la red externa.

2.2 Patrón arquitectónico

  • Separación de capas: Rutas → Controladores → Servicios → Base de datos
  • Stateless: Autenticación vía JWT en cookies httpOnly (sin estado en el servidor)
  • Modular: Cada entidad tiene su propio controller, service y route independientes
  • Soft delete: Ningún registro se elimina físicamente; se marca con fecha_eliminacion

4.3 Convenciones

  • Soft delete: columna fecha_eliminacion TIMESTAMP en todas las tablas operacionales. Todas las consultas deben filtrar con WHERE fecha_eliminacion IS NULL.
  • Zona horaria: todas las operaciones en America/Lima. Forzado en el pool de conexiones y en process.env.TZ del servidor.
  • Numeración modo CLÁSICO: formato {TIPO}-L{libro}-{numero} — Ejemplo: NAC-L1-45
  • Numeración modo CUI (RENIEC): código alfanumérico libre asignado por RENIEC.
  • Constraint MATRIMONIO: CHECK que obliga a que persona_secundaria_id no sea NULL cuando tipo_acta = 'MATRIMONIO'.

4.4 Orden de ejecución de migraciones

Ejecutar en orden estricto sobre la base de datos vacía:

psql -U postgres -d muni_union -f back/src/migrations/000_schema.sql
psql -U postgres -d muni_union -f back/src/migrations/001_refresh_tokens.sql
psql -U postgres -d muni_union -f back/src/migrations/002_indexes.sql
psql -U postgres -d muni_union -f back/src/migrations/003_usuario_permisos.sql
psql -U postgres -d muni_union -f back/src/migrations/004_usuario_permisos_modificar.sql
psql -U postgres -d muni_union -f back/src/migrations/005_seed_data.sql
⚠️
Todos los scripts usan IF NOT EXISTS — son idempotentes. Pueden ejecutarse más de una vez sin efectos secundarios.

07 Acceso Dual de Red

El sistema opera con dos puntos de entrada controlados por Nginx sobre una única instalación:

Entradaserver_name (Nginx)Rutas expuestasUsuarios
Portal público$PUBLIC_DOMAIN
(ej. verificar.muniunion.gob.pe)		/verificar/*
/api/verificar/*
/_next/*		Ciudadanos — cualquier red
Sistema interno$INTERNAL_DOMAIN
(ej. 192.168.1.100)		Todo el sistema completoTrabajadores — solo LAN
🔒
El firewall del servidor debe bloquear el puerto 443 del dominio/IP interno hacia internet. Solo el portal público debe ser accesible desde fuera de la red municipal.

08 Mantenimiento Automático

El servidor ejecuta tareas de limpieza periódicas cada 6 horas (definidas en server.js):

  • Limpieza de refresh tokens expirados: DELETE FROM refresh_tokens WHERE expires_at < NOW()
  • Purga de registros de auditoría: eliminación de registros con más de 2 años de antigüedad.

Adicionalmente, se recomienda configurar el backup automático diario de la base de datos:

# Agregar al crontab del servidor (cron diario a las 2:00 AM)
0 2 * * * /ruta/al/proyecto/scripts/backup_db.sh >> /var/log/backup_muni.log 2>&1

09 Importación Masiva

El endpoint POST /api/importacion/actas acepta carga masiva de registros históricos:

  • Archivo Excel (.xlsx) o CSV con columnas definidas
  • Archivo ZIP con PDFs opcionales (se vinculan automáticamente por nombre de archivo)
  • Límite: 30.000 filas por lote
  • Deduplicación automática por numero_acta + anio
  • Detección de homonimia por nombre completo + DNI
